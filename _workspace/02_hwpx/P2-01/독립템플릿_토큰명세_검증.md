## 3. 2026-09-17 원인 분리 및 누름틀 POC

- `{{F007VIA}}` 같은 일반 텍스트 토큰은 Kordoc HWPX 치환기의 지원 대상이 아님을 확인함. 공개 API `fillHwpx()`를 직접 호출해도 해당 텍스트 토큰은 `unmatched`로 남음.
- 한컴 Automation의 `CreateField(direction, memo, name)`으로 독립 사본에 `F007VIA` 누름틀을 만들고 HWPX로 저장함. 이 사본은 한컴 필드 목록과 Kordoc 구조 검증을 통과했으며, Kordoc의 `extractClickHereFields()`가 필드명·안내문을 정확히 읽음.
- 동일 사본에 최소 마스킹 JSON을 Kordoc `fillHwpx()` 공개 API로 적용한 결과, `F007VIA`가 `가상 경유`로 치환되고 기존 `{{F007VIA}}` 토큰은 재파싱 결과에서 사라짐. 생성본도 Kordoc 구조 검증을 통과함. 검증용 사본은 `artifacts/hwpx/P2-01/_diagnostic/`에만 보관함.
- 반면 `kordoc fill -j` CLI는 생성 F-007 사본과 누름틀 POC 사본에서 여전히 일반 오류를 반환함. 내장 `gian` 템플릿에서는 CLI가 정상 동작하므로, CLI 파일 입력 경로의 예외 처리 또는 한컴 저장본 조합 문제로 범위를 좁힘.
- 한컴 Automation으로 21개 필드를 한 번에 연속 생성·저장하는 시도는 이 환경에서 응답 지연이 발생했으므로 중단함. 원본·기존 템플릿을 덮어쓰지 않았고, 이 작업에서 생성한 Automation HWP 프로세스만 종료함.

## 4. 확인된 제약과 다음 조치

1. `npx -y kordoc@^4 fill <F-007 템플릿> -j <마스킹 JSON>`은 “문서 처리 중 오류”로 종료됨. 두 개의 인식 필드만 담은 최소 JSON에서도 동일하게 실패하여, JSON 크기나 값 범위 문제가 아님을 확인함.
2. 독립 템플릿은 원문 페이지의 내용·표·이미지를 기준으로 새 HWPX로 생성한 작업 사본임. 복합 원본에서 OOXML 구간을 보존해 잘라낸 원본 동일 조판본은 아님.
3. F-013 렌더는 이미지 55개를 인식했으나, 11쪽 복합 표에서 페이지 걸침 경고가 발생함. 한컴 수동 열기와 원본 PDF 쪽별 대조가 필수임.
4. 따라서 P2-01은 완료 처리하지 않음. 다음 우선 조치는 F-007 21개 필드를 한컴 UI 또는 안정적인 단일 필드 저장 루프로 전환한 뒤, Kordoc API 전체 마스킹 치환·재열기·PDF·한컴 화면 대조를 통과시키는 것임. CLI `fill -j`는 별도 최소 파일로 재현·업스트림 원인 확인이 필요함.
